# Complete Docker-First Migration Guide: SQL Server ➔ PostgreSQL

This guide explains **how to run, check, and verify the migration** using **100% Docker**.

You do **not** need Python, database drivers, or dependencies installed locally on your computer. Everything runs cleanly via **Docker Compose**.

---

## 1. Background & Context

- **Client Database**: The client has not provided their database yet.
- **Sample Database**: As agreed with Nivedha, we created a **complex sample SQL Server database** (**26 tables** across `core`, `inventory`, `sales`, and `audit` schemas) featuring primary keys, foreign keys, identity columns, self-referential trees, composite keys, check constraints, filtered indexes, and realistic seed data.
- **Canonical Data Model (CDM)**: Instead of an ad-hoc copy, we normalize everything into clean PostgreSQL schemas:
  - Names are converted from PascalCase to clean `snake_case`.
  - Data types are mapped to PostgreSQL standards (`DATETIME2` ➔ `TIMESTAMPTZ`, `BIT` ➔ `BOOLEAN`, `UNIQUEIDENTIFIER` ➔ `UUID`).
  - Auto-increment columns use standard `GENERATED BY DEFAULT AS IDENTITY`.

---

## 2. Step 1: Start Databases & Auto-Seed

In your terminal, navigate to the project directory and run:

```bash
docker compose up -d
```

### What this does:
1. Starts **SQL Server 2022** container (`sqlserver_source` on port `1433`).
2. Starts **PostgreSQL 16** container (`postgres_target` on port `5434`).
3. Runs the `seed` container automatically to create and populate the 26-table `EnterpriseSalesERP` database in SQL Server.

---

## 3. Step 2: Check the Source Database & Data

Run the containerized database inspector:

```bash
docker compose run --rm check
```

### What it displays:
1. Connects to SQL Server (`EnterpriseSalesERP`).
2. Displays all **26 tables** and their current **row counts**.
3. Displays **sample rows** from `core.Customers` (Customer ID, Company, Contact, Email, Credit Limit) and `sales.Orders`.
4. Shows the current status of PostgreSQL and local MySQL port (3306).

---

## 4. Step 3: Run the Migration

To migrate the schema and all data from SQL Server to PostgreSQL, run:

```bash
docker compose run --rm migrate
```

### What the `migrate` container does automatically:
1. **Reads Metadata**: Discovers all 26 tables, columns, primary keys, and types from SQL Server.
2. **Generates Canonical PostgreSQL Schema**: Converts tables and columns to clean `snake_case` with proper PostgreSQL types (`TIMESTAMPTZ`, `BOOLEAN`, `UUID`, `NUMERIC`, `IDENTITY`).
3. **Creates Tables in PostgreSQL**: Creates schemas (`core`, `inventory`, `sales`, `audit`) and target tables.
4. **Migrates Data**: Streams rows from SQL Server to PostgreSQL, converting data types in flight.
5. **Syncs Identity Sequences**: Resets PostgreSQL sequence counters so future inserts continue at `MAX(id) + 1`.
6. **Validates & Reconciles**: Compares source row counts against target row counts and prints a summary table showing **100% Match**.
7. **Saves Output Files**:
   - [`output/postgres_schema.sql`](file:///c:/Users/aks89/Desktop/mysql-to-postgres/output/postgres_schema.sql): Complete PostgreSQL DDL generated from the Canonical Model.
   - [`output/validation_report.md`](file:///c:/Users/aks89/Desktop/mysql-to-postgres/output/validation_report.md): Audit report confirming 100% row reconciliation across all 26 tables.

## 5. Step 4: Verify the Target PostgreSQL Database

Run the inspector again:

```bash
docker compose run --rm check
```

Section 2 in the output will show all 26 tables populated in PostgreSQL with their row counts and sample customer records.

### Optionally, Query PostgreSQL Directly:
```bash
# Query customer records (notice clean snake_case columns):
docker exec postgres_target psql -U postgres -d enterprisedb -c "SELECT customer_id, company_name, contact_name, email, credit_limit FROM core.customers LIMIT 5;"

# Query orders:
docker exec postgres_target psql -U postgres -d enterprisedb -c "SELECT order_id, order_number, total_amount, payment_status FROM sales.orders;"

# Test sequence auto-increment:
docker exec postgres_target psql -U postgres -d enterprisedb -c "INSERT INTO core.customers (contact_name, email, credit_limit) VALUES ('New Client', 'client@test.com', 5000.00) RETURNING customer_id;"
```
*(Inserting a new customer returns `1009`, proving the sequence resumed seamlessly after the seed data without primary key collisions!)*

## 7. How to Migrate the Real Client Database

All database connection parameters and credentials are externalized to `.env` (never hardcoded in code):

When the client provides their database credentials:
1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
2. Enter the client's host, port, user, password, database, and schemas under `MSSQL_*`.
3. Enter your destination PostgreSQL connection details under `PG_*`.
4. Run:
   ```bash
   docker compose run --rm migrate
   ```
The container dynamically extracts the client's schema, converts it to the Canonical Data Model, creates the PostgreSQL tables, migrates the data, and validates the counts.
